# VKIntox v0.3.0 Preview 2 is out! 🎉

A preview focusing on framegen fixes and the overlay's new look.

This is a **Preview release**, meaning it may have rough edges, is a testing build, and is not the final shape of what v0.3.0 will be. Frame generation is still experimental and off by default. It has been tested primarily with Roséline/Roblox.

## What's new from Preview 1:

- **Lots of frame generation fixes**: adaptive frame insertion, some fixes for FX-Over-UI for framegen, and async model loading work. Model warmup now waits for the game's swapchain to settle. There are also some frame presentation-related refactors.

- **Yet another UI overhaul**: The UI now looks much more closer to Material 3 Expressive. Extensive UI fixes were done, too. Open/Close animations changed to a scale-based animation. Add Effects no longer has an oversized hero, and has received some tweaks. Preset actions are now folded into one button. Lots of fixes to Effect Parameters, too.

- **Preset exporting**: you can now export your preset from the main view.

**Full Changelog**: https://git.buwryy.net/VKIntox/VKIntox/compare/v0.3.0-preview.1...v0.3.0-preview.2

#### Install (Universal)

```bash
curl -fsSL https://vkintox.buwryy.net/setup | bash
```

Includes [Sober](https://sober.vinegarhq.org) and Roblox-on-Rosemary/[Roséline](https://roseline.buwryy.net) support.

> When installing for Flatpak, set `ENABLE_VKINTOX=1` on the game itself, not its launcher. The Flatpak layer targets `org.freedesktop.Platform` 26.08.

### Other, boring, non-user-siding changes:

- Keyboard events now reach ImGui through a queued X11/Wayland path, which fixes it being dropped between frames.
- Headless testing coverage grew for cookie geometry and AA, button press/release shapes, and dialog sizing.
- Model paths, package overrides, status messages, environment isolation, precision selection, and file-descriptor cleanup are handled explicitly.
- Setup fetches the MAKO package from Forgejo or GitHub, seeds missing packages, replaces legacy Arch installs, and supports dry runs. Builds can now disable the FG engine with `-Dfg_engine=false`.
